# 요구사항

대규모 트래픽 선착순 쿠폰 발급 시스템. **주어진 요구사항이므로 임의로 고치지 않는다.** 이 문서를 어떻게 풀지는 [README.md](README.md) 와 버전별 문서에 적는다.

---

## 전체 조건

- 개인정보는 로그와 응답 데이터 등에서 반드시 마스킹 처리한다.
- 쿠폰과 캠페인 정보는 가상으로 생성한다. 쿠폰 종류와 할인 정책 등 기획은 팀 자유다.
- 가상 유저 100만 명과 발급 이력 300만 건 더미데이터를 생성하여 적재한다. 생성과 적재 속도 자체는 평가하지 않는다.
- 알림 발송 등 외부 연동은 Mocking 처리한다.

---

## 쿠폰 발급 시스템

- 한정 수량 쿠폰을 선착순으로 발급한다.
- **재고 10,000장에 20,000명이 동시에 요청해도 초과 발급 0건, 1인 최대 1매.**
- 트래픽이 몰리는 상황을 부하 테스트로 직접 재현하여 시연한다.
- 도구는 자유다(JMeter, k6, 자작 클라이언트 등). 시작 가이드가 제공되며 도구와 처리량은 평가하지 않는다.
- (선택) 오픈 시각 예약, 발급 현황 실시간 조회 등 확장.

---

## 쿠폰 정합성 검증

- 발급, 사용, 취소, 만료 등 쿠폰의 **전체 상태**를 관리한다. 동일한 상태 변경 요청이 반복해서, 또는 동시에 발생해도 한 번만 반영되어야 한다.
- 어떤 상황에서도 이력과 재고가 어긋나지 않아야 하며, **이를 스스로 검증할 수 있는 수단**(검증 쿼리, 검증 배치 등)을 함께 구현한다.
- 검증은 **300만 건 전체**를 대상으로 하며, 같은 데이터 기준으로 재실행하면 같은 결과가 나와야 한다. 실행 시간은 평가하지 않는다.
- (선택) 검증 결과 리포트 자동화.

---

## 선착순 쿠폰 기획

유통기한 임박한 재고 떨이.

```
대상 정렬   유통기한 임박순 -> 판매율 저조한 상품순
혜택        상품 금액에서 30% 차감 (정률 할인)
발급 방식   선착순
```
