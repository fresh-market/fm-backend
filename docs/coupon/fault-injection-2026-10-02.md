## 3. 걸린 재연결 재건과 못 한 재건

**G-2 에서 이것이 남았다.**

```
16:18:24.937  COUPON_SEQ_RECONNECT_DETECTED couponId 2건
16:18:28.209  COUPON_SEQ_CONTRIBUTIONS_TIMEOUT couponId=1000000 instances=3 done=2 waitedMillis=3000
16:18:28.211  COUPON_SEQ_REBUILD_SKIPPED       couponId=1000000 reason=reprepared
16:18:30.260  COUPON_SEQ_REBUILD_SKIPPED       couponId=900001 reason=pause-timeout
```

**주입이 01:17:47(UTC 16:17:47)이고 감지가 16:18:24 다.** 37초 뒤에 Lettuce 가 다시 붙었고
감시기가 그것을 승격으로 읽었다. **설계가 의도한 그대로 돌았다.**

### 둘 다 건너뛴 자리

| 쿠폰 | 사유 | 무슨 뜻인가 |
|---|---|---|
| 1000000 (워밍업) | `reprepared` | 카운터가 0 이라 이미 다시 준비된 것으로 봤다 |
| **900001 (시험)** | **`pause-timeout`** | **플러셔를 2초 안에 못 멈췄다** |

**`pause-timeout` 이 이 회차가 찾아낸 것이다.** 재건은 쓰는 동안 플러셔를 멈춰야 하는데,
페일오버 구간의 플러셔는 Redis 응답을 기다리느라 멈추지 못한다. `PAUSE_TIMEOUT` 이 2초이고
그 안에 못 멈추면 재건이 포기한다.

```java
if (!flusher.pause(PAUSE_TIMEOUT)) {
    log.warn("event=COUPON_SEQ_REBUILD_SKIPPED couponId={} reason=pause-timeout", couponId);
    return;
}
```

**모순이 여기 있다.** 재건이 필요한 때가 바로 Redis 가 흔들리는 때인데, 그때가 플러셔를 멈추기
가장 어려운 때다. **재건을 거는 데는 성공했고 재건을 하는 데는 실패했다.**

### 재건 소요 시간을 못 잰 까닭

**이 회차의 재건은 한 번도 완주하지 않았다.** `COUPON_SEQ_REBUILT` 가 0건이다.

지금까지 재건 소요 시간의 실측은 둘뿐이고 둘 다 다른 경로에서 나왔다.

| 언제 | 어떤 경로 | 올리기 | 기다림 | 읽고쓰기 | 합계 |
|---|---|---:|---:|---:|---:|
| 2026-09-23 | `seq-loss`, 부하 중 | 21 | 55 | 127 | **204ms** |
| 2026-10-01 | 재연결(기동 오탐), 부하 끝난 뒤 | 67 | 3,026 | 364 | **3,458ms** |

**승격 경로에서 완주한 재건의 시간은 아직 없다.**

## 4. 앞 회차와 견주면

**같은 세대끼리만 견준다.** 2026-10-01 회차는 워밍업이 3,000 / 동시성 20 이었고 이 회차는
20,000 / 300 이다.

| 건 장애 | 2026-10-01 | 2026-10-02 |
|---|---:|---:|
| 서버 1대 비정상 종료 | 0.089초 | **0.055초** |
| 캐시 페일오버 | 0.084초 (OOM 으로 왜곡) | 0.879초 |
| 복합 | 0.210초 | **0.230초** |

**캐시 페일오버의 0.084초는 합격이 아니었다.** 그 회차는 세 대가 OOM 으로 죽어 느린 응답이
판정 전에 사라졌고 발급이 5,741 에 그쳤다. **이번에는 OOM 없이 9,910 을 팔고 0.879초다.**

**이번 회차에 OOM 이 없는 것이 큰 차이다.** 메모리 한도는 그대로인데 혼잡이 503 으로 빨리
끊겨 쌓이는 일이 줄었기 때문으로 보이지만, 이 회차로 단정하지 못한다.

## 5. 남은 것

```
1  pause-timeout 을 어떻게 다룰지 정한다      재건이 가장 필요한 때 가장 안 걸린다
2  승격 경로에서 완주한 재건의 시간을 잰다     아직 한 번도 못 쟀다
3  컨테이너 메모리 한도를 둔다                 fm-infra 의 미결정 값 2.1.1
4  G-1 의 already_issued 5,209 를 설명한다     잔재로 보이지만 확인 안 했다
```

**1번이 설계로 돌아가는 질문이다.** 선택지가 셋으로 보인다.

```
가  PAUSE_TIMEOUT 을 늘린다          그만큼 발급이 더 멈춘다
나  멈추지 못해도 재건을 진행한다      미확정이 확정을 덮을 수 있다
다  그대로 둔다                       승격 뒤 재건을 포기하는 것이다
```

**지금은 다 번이고, 그것이 의도인지 아닌지가 기록에 없다.**
