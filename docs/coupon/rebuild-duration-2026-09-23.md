# 재건이 문을 닫아 둔 시간을 처음 잰 회차 (2026-09-23)

**그동안 "재건 정지 3.4초" 라고 써 왔는데 계산값이었다.** 설정값 3,000밀리초와 앞선 회차의 읽고 쓰기 427밀리초를 더한 것이지 실측이 아니다. 이번에 네 구간을 전부 재는 계측을 붙이고 돌렸다.

```
AWS 실측   20,000 VU / ramp 60초 / 재고 10,000장 / 전용 인스턴스 3대
앱         fm-backend main cbb46dee
주입       레디스 장애와 인스턴스 + 레디스 장애. DB 장애는 넣지 않았다
```

## 1. 결론

| | 회차 1 `seq-loss` | 회차 2 `app+seq-loss` | 회차 3 `app+seq-loss` |
|---|---:|---:|---:|
| 큐 수집 대기 | 55 | 2 | **3,016** |
| 주도자 기여 | 21 | 8 | 14 |
| 읽고 쓰기 | 127 | 123 | 161 |
| **재건 총 소요** | **204** | **135** | **3,193** |

**정상 조건에서 204밀리초다.** 3.4초는 열여섯 배 과대평가였다.

**세 회차 전부 초과 발급 0 이고 1인 1매가 지켜졌다.** 모두 `10000 / 10000 / 결번 0 / 회원 10000` 이다.

## 2. 계산값이 왜 그렇게 빗나갔나

두 항 모두 실제보다 컸다.

```
큐 수집 대기   3,000 (설정값)  ->    55 (실측)
읽고 쓰기        427 (옛 측정)  ->   127 (실측)
```

**앞의 것은 조기 종료가 붙기 전의 값이다.** 이제는 명부의 수만큼 표시가 차면 그 자리에서 끝내므로 설정값을 다 안 쓴다.

**뒤의 것은 결번 수에 비례한다.** 427밀리초는 결번 799개일 때의 값이고, 이번 세 회차는 `freed=0` 이라 훨씬 가벼웠다. **회차마다 달라지는 값을 상수처럼 써 온 것이 문제였다.**

## 3. 죽은 인스턴스 하나가 열여섯 배를 만든다

회차 2와 3은 **같은 주입인데 결과가 스물세 배 갈렸다.** 차이는 죽이기와 키 삭제 사이의 간격 하나다.

```
회차 2   11초 차   instances=2  done=2   waitMillis    2
회차 3    1초 차   instances=3  done=2   waitMillis 3,016
```

`STALE_AFTER` 가 10초다. **11초가 지나면 죽은 대가 명부에서 빠져 주도자가 안 기다린다.** 1초면 아직 남아 있어 **영영 안 올 기여를 천장까지 기다린다.**

```
COUPON_SEQ_CONTRIBUTIONS_TIMEOUT couponId=900001 instances=3 done=2 waitedMillis=3000
```

**`STALE_AFTER` 10초가 재건 정지 시간에 그대로 얹힌다.** 인스턴스가 죽고 10초 안에 레디스 키가 사라지면 이 일이 난다. **ASG 교체나 배포 중에 충분히 겹칠 수 있는 창이다.**

### 값을 줄이면 되나

**안전과 속도를 맞바꾸는 자리다.** 짧게 잡으면 이 구간이 줄지만, 살아 있는데도 명부에서 빠지는 인스턴스가 생긴다. 그러면 주도자가 그 인스턴스의 큐를 안 기다리고 키를 세워 **그 번호들을 남에게 다시 내준다.**

명부의 실수는 **덜 기다리는 쪽만 위험하다.** 더 기다리는 것은 3초를 넘지 않는다.

## 4. 이 수치를 읽을 때의 한계 셋

**세 회차 모두 큐가 비어 있었다**(`queued=0`, `freed=0`). 읽고 쓰기가 가장 가벼운 조건의 값이다. 앞선 회차에서 `freed=5753` 이 나온 적이 있으니 그때는 훨씬 컸을 것이다.

**감지 지연이 안 들어 있다.** 카운터가 사라진 때가 아니라 주도자가 일을 시작한 때부터다. **실제 정지는 이 값보다 길다.**

**k6 요약을 안 거뒀다.** `size` 와 시간 측정에 집중하다 빠뜨렸고 인프라를 내려 이제 못 가져온다. 정합성 수치는 DB 에서 받아 적었다.

## 5. 회차 1에서 재건이 두 번 걸렸다

한 대가 `CONTRIBUTIONS_TIMEOUT instances=3 done=1` 로 3초를 다 쓰고 `REBUILD_SKIPPED` 로 끝났다. 다른 대가 먼저 문을 열어서다.

**락이 있는데 두 주도자가 동시에 뛴 셈이다.** 쿠폰이 둘(`900001`, `1000000`)이고 `seq-loss` 가 둘의 카운터를 다 지우므로 그것과 얽혔을 수 있다. **아직 안 밝혔다.**

## 6. 다음에 할 것

1. **큐가 찬 상태로 다시 잰다.** `readWriteMillis` 가 결번 수에 어떻게 비례하는지 봐야 이 값을 쓸 수 있다
2. **감지 지연을 잰다.** 카운터가 사라진 때부터 주도자가 시작할 때까지다. 그것까지 더해야 진짜 정지 시간이다
3. **`STALE_AFTER` 를 어떻게 할지 정한다.** 10초가 정지에 얹히는 것을 봤으니 근거가 생겼다
4. 회차 1의 이중 재건을 밝힌다
