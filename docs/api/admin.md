# 관리자

관리자 계정 자체를 다룬다. `admin` 도메인은 `admin` 과 `audit_log` 두 테이블을 갖는다
([domain-map.md](../code-architecture/domain-map.md)).

**관리자가 회원이나 상품을 관리하는 API 는 여기 없다.** 그것들은 조작 대상 리소스를 가진 도메인에 있다.

| 관리자가 하는 일 | 문서 |
|---|---|
| 관리자 계정 발급, 비활성화 | 이 문서 |
| 로그인, 비밀번호 변경 | [auth.md](./auth.md) |
| 회원 목록, 차단, 등급 | [member.md](./member.md) |
| 상품, 카테고리, 리뷰, Q&A | [product.md](./product.md) |
| 로트 입고, 재고 조정, 폐기 | [stock.md](./stock.md) |
| 주문 관리, 클레임 승인, 배송 | [order.md](./order.md) |
| 쿠폰과 캠페인 | [coupon.md](./coupon.md) |

**경로가 `/v1/admin/` 으로 시작한다고 해서 `admin` 도메인인 것은 아니다.**
경로는 소비자를 가르고(`API-2-08`), 도메인은 조작 대상 리소스를 따른다.
`/v1/admin/members` 는 `member` 테이블을 다루므로 `member` 도메인이다.

## 관리자 계정

```
GET    /v1/admin/admins
POST   /v1/admin/admins
DELETE /v1/admin/admins/{adminId}
```

**최고관리자만 할 수 있다** (`SUPER_ADMIN`). 나머지는 `403` 이다.

```json
{ "loginId": "admin.lee", "name": "이관리", "role": "ADMIN" }
```

| 필드 | 필수 | 제약 |
|---|---|---|
| `loginId` | O | 50자 이하. 중복 불가 |
| `name` | O | 50자 이하 |
| `role` | O | `ADMIN` 또는 `SUPER_ADMIN` |

임시 비밀번호를 발급한다. 비밀번호 변경 기능은 현재 구현 범위에 포함하지 않는다.

**삭제는 하드 삭제가 아니라 비활성화다.** 이력 테이블 다섯이 `admin_id` 를 참조해 지울 수 없다.
비활성화하면 리프레시 토큰을 비운다. Access 토큰의 즉시 무효화 처리는 관리자 비활성화 구현 시 별도로 연동한다.

| 오류 | 코드 | 언제 |
|---|---|---|
| `403` | `ADMIN-005` | 최고관리자가 아니다 |
| `409` | `ADMIN-006` | 아이디 중복 |
| `409` | `ADMIN-007` | 본인은 비활성화할 수 없다 |
| `409` | `ADMIN-008` | 마지막 최고관리자는 비활성화할 수 없다 |

## 정하지 못한 것

**감사 로그 조회 API 가 없다.** `audit_log` 는 이 도메인의 테이블인데 읽는 경로를 정하지 않았다.
요구사항은 관리자 주요 행위(상품 삭제, 환불, 등급 변경, 권한 변경)와
인증 이벤트(로그인 성공과 실패, 토큰 재발급, 로그아웃)를 기록하라고 한다.

**기록만 하고 보지 않으면 남길 이유가 없으므로 조회 경로가 필요하다.**

한 가지 제약이 걸린다. `audit_log.admin_id` 가 `NOT NULL` 이라
**회원의 인증 이벤트와 주체를 모르는 로그인 실패를 담을 수 없다.**
인증 이벤트까지 이 테이블로 받으려면 컬럼을 널 허용으로 바꾸거나 테이블을 나누는 마이그레이션이 필요하다.

**로그인 5회 실패 시 30분 잠금은 현재 프로젝트 구현 범위에서 제외한다.**
`admin` 에 실패 횟수와 잠금 시각 컬럼도 두지 않는다.
근거와 응답 설계는 [auth.md](./auth.md) 끝에 적어 두었다.
